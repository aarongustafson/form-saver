<form-saver>

Save drafts from a native form and restore them on a later visit. Without JavaScript, the form remains usable, but drafts aren’t saved. See the README for installation and API documentation.

Read the README View on GitHub esm.sh example unpkg example

Explore the behavior-only demo for scripts without storage hooks, or the encrypted draft demo for application-owned asynchronous storage transformations.

Use invented details: drafts are stored in this browser’s localStorage, including message text. Any script running on this origin can read them. Passwords and files are excluded. The retention checkbox controls what remains after submission, not whether drafts are saved.

Each example uses its own storage-key so drafts don’t overwrite one another. Load the feedback module before registering the component with define.js to show the authored data-error message when storage fails. This is demo UI, not a component attribute or a saved/restored notification.

If JavaScript is unavailable, or if the module fails to load, the forms and their native validation still work, but drafts aren’t saved. Keep a copy before leaving. These examples use a placeholder /contact endpoint; no working submission service is provided.

Save and restore a draft

Wrap the first form in <form-saver>. Type into it, pause briefly for autosave, and refresh the page to see values restored. 

<form-saver storage-key="demo:basic">
  <form action="/contact" method="post">
    <label>
      Name
      <input name="name" autocomplete="name" />
    </label>
    <label>
      Email
      <input name="email" type="email" autocomplete="email" />
    </label>
    <label>
      Message
      <textarea name="message"></textarea>
    </label>
    <button type="submit">Send</button>
  </form>
  <p class="draft-feedback" role="status"
    data-error="Draft storage is unavailable. Your entered values remain in the form. Keep a copy before leaving."></p>
</form-saver>

Retaining specific fields

The retain attribute takes a space-separated list of field names (or IDs as a fallback) that should remain in storage during post-submit cleanup. This is useful for contact forms where you want to pre-populate the sender’s name and email address on their next visit, but not their message.

The component clears the full draft on pagehide following a submit it observed as uncanceled. It doesn’t check the response, confirm server acceptance, or reset the current form. A server rejection can still be followed by cleanup. For application-controlled submission, cancel the event before the component’s listener runs, then call clearSavedData() after your application confirms acceptance. See the submission reference.

Using the retain attribute

After a submit followed by leaving this page, return to this example. The Name and Email fields can be restored; Message is not retained. The placeholder endpoint cannot confirm delivery. 

<form-saver
  retain="name email"
  storage-key="demo:retain-fields">
  <form action="/contact" method="post">
    <label>
      Name
      <input name="name" autocomplete="name" />
    </label>
    <label>
      Email
      <input name="email" type="email" autocomplete="email" />
    </label>
    <label>
      Message
      <textarea name="message"></textarea>
    </label>
    <button type="submit">Send</button>
  </form>
  <p class="draft-feedback" role="status"
    data-error="Draft storage is unavailable. Your entered values remain in the form. Keep a copy before leaving."></p>
</form-saver>

Let people choose post-submit retention

The retain-choice attribute inserts a labeled opt-in checkbox into the form. If the user leaves it unchecked (the default), the selected fields are removed from storage during post-submit cleanup too. Autosave still runs while typing: this checkbox is not consent to draft storage. Obtain any required consent before enabling the component. You can customize the checkbox with retain-choice-label and retain-choice-container.

Simple opt-in: retain-choice

Add retain-choice alongside retain and <form-saver> will automatically inject a labelled checkbox directly before the submit button. The default label is “Store my contact information for later”. 

<form-saver
  retain="name email"
  retain-choice
  storage-key="demo:retain-choice-basic"
>
  <form action="/contact" method="post">
    <label>
      Name
      <input name="name" autocomplete="name" />
    </label>
    <label>
      Email
      <input name="email" type="email" autocomplete="email" />
    </label>
    <label>
      Message
      <textarea name="message"></textarea>
    </label>
    <button type="submit">Send</button>
  </form>
  <p class="draft-feedback" role="status"
    data-error="Draft storage is unavailable. Your entered values remain in the form. Keep a copy before leaving."></p>
</form-saver>

Custom label: retain-choice-label

Use retain-choice-label to provide label text that fits your application’s vocabulary, or to translate the generated checkbox. 

<form-saver
  retain="name email"
  retain-choice
  retain-choice-label="Remember my details next time"
  storage-key="demo:retain-choice-label"
>
  <form action="/contact" method="post">
    <label>Name <input name="name" autocomplete="name" /></label>
    <label>Email <input name="email" type="email" autocomplete="email" /></label>
    <label>Message <textarea name="message"></textarea></label>
    <button type="submit">Send</button>
  </form>
  <p class="draft-feedback" role="status"
    data-error="Draft storage is unavailable. Your entered values remain in the form. Keep a copy before leaving."></p>
</form-saver>

Translate the checkbox and recovery message

Set retain-choice-label for the generated checkbox. Translate your own field labels, buttons, and data-error feedback separately. This French example sets lang="fr" on its live form. The checkbox still controls only post-submit retention. 

<form-saver
  lang="fr"
  retain="name email"
  retain-choice
  retain-choice-label="Conserver mes coordonnées pour la prochaine fois"
  storage-key="demo:retain-choice-fr">
  <form action="/contact" method="post">
    <label>Nom <input name="name" autocomplete="name" /></label>
    <label>Adresse e-mail <input name="email" type="email" autocomplete="email" /></label>
    <label>Message <textarea name="message"></textarea></label>
    <button type="submit">Envoyer</button>
  </form>
  <p class="draft-feedback" role="status"
    data-error="Le stockage du brouillon est indisponible. Vos réponses restent dans le formulaire. Gardez une copie avant de quitter cette page."></p>
</form-saver>

Custom placement: retain-choice-container

By default the checkbox is inserted immediately before the submit button. If your form layout requires it elsewhere — say, inside a dedicated actions bar or a privacy notice area — point retain-choice-container at a CSS selector that matches the container element you want. The checkbox wrapper will be appended inside that element. 

<form-saver
  retain="name email"
  retain-choice
  retain-choice-label="Remember my details next time"
  retain-choice-container=".form-footer"
  storage-key="demo:retain-choice-container"
>
  <form action="/contact" method="post">
    <label>
      Name
      <input name="name" autocomplete="name" />
    </label>
    <label>
      Email
      <input name="email" type="email" autocomplete="email" />
    </label>
    <label>
      Message
      <textarea name="message"></textarea>
    </label>
    <div class="form-footer">
      <button type="submit">Send</button>
    </div>
  </form>
  <p class="draft-feedback" role="status"
    data-error="Draft storage is unavailable. Your entered values remain in the form. Keep a copy before leaving."></p>
</form-saver>
