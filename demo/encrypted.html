Application-owned storage transformations

The module’s initialize(saver, { signal }) export configures the optional beforeSave and beforeRestore callbacks. For a script that doesn’t configure storage hooks, see the writing-help example.

Use invented details only. This example uses a public, predictable demo key, so anyone can decrypt its drafts. It demonstrates the hooks, not secure key management or GDPR compliance.

Type a name or message, wait briefly for autosave, then reload to restore it. Inspect the demo:encrypted localStorage entry to see the version, algorithm, fresh IV, and ciphertext instead of field values. The module uses Web Crypto AES-GCM in your browser without sending values or keys. The native form still submits to its action when you press Send.

Save the complete module beside your page and register the component with define.js. If loading or a transformation fails, the component reports an error; it doesn’t retry with plaintext. Failed decoding preserves the stored payload and current fields. New edits take precedence over delayed restoration. Use a new storage key or an explicit migration policy for existing plaintext drafts. See the storage hooks reference for ordering, replacement, and navigation limits.

The feedback module displays the authored data-error message below the form. Load it before registration to catch initial errors. Translate this text and the checkbox’s retain-choice-label for your application.

A real application must replace the demo key with one authorized by its backend session, never store the key alongside the draft, and revoke access on logout or session expiry. Encryption cannot protect against malicious same-origin scripts, or another person whose browser session still authorizes the key.

The retention checkbox controls stored fields during post-submit cleanup, not consent to autosave while typing. An uncanceled submit followed by pagehide is not confirmation of server acceptance. Asynchronous saves may not finish if you immediately close or leave the page. Without JavaScript, or if the module fails, the native form remains usable but drafts are not saved. Keep a copy before leaving. The /contact endpoint is a placeholder, not a submission service. Web Crypto requires HTTPS or localhost. 

<form-saver
  script="./draft-storage.js"
  storage-key="demo:encrypted"
  retain="name email"
  retain-choice
>
  <form action="/contact" method="post">
    <label>Name <input name="name" autocomplete="name" /></label>
    <label>Email <input name="email" type="email" autocomplete="email" /></label>
    <label>Message <textarea name="message"></textarea></label>
    <button type="submit">Send</button>
  </form>
  <p class="draft-feedback" role="status"
    data-error="Draft encryption or storage is unavailable. Your entered values remain in the form. Keep a copy before leaving."></p>
</form-saver>
